# CountryCode-Decide

### Messy country names → ISO 3166 codes, with a calibrated "I don't know"

A small open model that reads a country or US state the way registers and forms write it —<br>
misspelled, abbreviated, historical, in many languages — on your own machine:<br>
75 MB, about 4 ms per string on a CPU.

Company registers, onboarding forms and scanned documents write countries as free text:
`Østerrike`, `Deleware`, `England and Whales`, `BRITHISH VIRGIN ISLANDS`, `10250 THAILAND`, `n/a`.
Downstream systems need ISO codes. Rule libraries miss most foreign-language and misspelled
forms, fuzzy matching makes confident false hits (`n/a` → `NA`, Namibia's code), and
general-purpose language models are slow and give no usable signal of when they are unsure.

CountryCode-Decide returns a typed answer, never free text — an ISO 3166-1 alpha-2 country code
(250 codes: the 249 ISO codes + `XK` Kosovo), an ISO 3166-2:US state code (`US-CA`, … 50 states +
`US-DC`) when the place is in the US, or "not a country" — with a calibrated probability. When it
cannot meet the error rate you ask for, it **abstains** and sends the string to a person, with a
short candidate list:

| Input | Context | Answer at the 5 % error target | Confidence |
|---|---|---|---|
| `Østerrike` | country field, NO register | **AT** Austria | 0.99 |
| `Untted Klngdom` | country field | **GB** United Kingdom | 0.95 |
| `England and Whales` | country field, GB register | **GB** United Kingdom | 0.96 |
| `BRITHISH VIRGIN ISLANDS` | country field | **VG** British Virgin Islands | 0.98 |
| `10250 THAILAND` | country field | **TH** Thailand | 1.00 |
| `Nederländerna` | country field, SE register | **NL** Netherlands | 0.99 |
| `中华人民共和国` | country field | **CN** China | 0.88 |
| `W. Germany` | country field | **DE** Germany | 1.00 |
| `Calif` | jurisdiction field, US register | **US-CA** California | 0.97 |
| `Georgia` | jurisdiction field, US register | **US-GA** Georgia | 0.93 |
| `Georgia` | none | abstains → review (candidates GE, US-GA) | 0.75 |
| `Europe` | country field | **NONE** not a country or US state | 1.00 |
| `n/a` | country field | abstains → review (candidates NE, NONE, ZA) | 0.12 |
| `Deutchland` | country field | abstains → review (candidates DE, US-SD) | 0.47 |
| `Czechoslovakia` | country field | abstains → review (candidates CZ, SK) | 0.50 |

The examples were chosen by hand to show the behaviour; the answers are the release model's real
output ([`results/`](results/), generated by `scripts/run_examples.py`). Accuracy is measured below.

All numbers in this README are generated from [`results/`](results/) by `scripts/make_docs.py`.
The fresh registers — every distinct value of the jurisdiction and country fields of New York and
Oregon — were never used for training, calibration or model selection, and were read once after a
frozen pre-registration (release 1.2). This release (1.2.1) keeps the same weights and corrects the
certificate after an external review (see [Accuracy](#accuracy)); its numbers on the fresh
registers are therefore post-hoc.

**Where the model helps, and where a lexicon is enough.** Most fresh-register strings are standard
names, and an exact lexicon that applies the same context rules as the training labels (`CA` is
California in a US jurisdiction field) does as well as the model there:

| Predictor | automatic labels (exact lexicon match, n = 261) | hand-labelled (n = 100) | hand-labelled answered |
|---|---|---|---|
| CountryCode-Decide (always answers) | 99.2 % | 61.0 % | 100 |
| CountryCode-Decide at the certified 5 % target | 98.1 % | 56.0 % | 61 |
| Zero-shot LLM (qwen3.5_35b-a3b-q4_K_M) | 94.3 % | 61.0 % | 97 |
| Lexicon + context rules | 99.6 % | 63.0 % | 62 |
| multilingual-e5-small nearest name | 100.0 % | 37.0 % | 100 |
| exact lexicon match | 100.0 % | 24.0 % | 23 |

Automatic labels come from an exact lexicon match, so a lexicon is right on them by construction;
the hand-labelled strings are the hard part, and there the model, the LLM and the context lexicon
are about level. The model earns its place on messier strings. On held-out strings of the training registers (656 strings, many misspelled or abbreviated; other strings of the same registers were in training) the model is right on 82.6 %, the best other predictor (qwen3.5_35b-a3b-q4_K_M zero-shot) on 73.8 %, the lexicon with context rules on 35.8 %; on the 472 of them with no exact lexicon match 81.1 % against 73.1 %. On GBIF's curated list the LLM is better: 69.6 % against 58.8 %. In practice:
look strings up in a lexicon with context rules first, and send what it cannot read to the model,
which answers what it can at the certified error rate and abstains on the rest.

## Why CountryCode-Decide

| | |
|---|---|
| **Codes, not text** | Every answer is a probability over a fixed label space: 250 country codes, 51 US state codes and "not a country". Nothing is generated, so it cannot invent a code that does not exist. It can still be wrong with high confidence, which is why a person reviews abstentions and candidate lists. |
| **Says "I don't know" — with a certificate** | Thresholds are chosen by a fixed-sequence test (Learn-then-Test) on held-out real register strings, counted once per register and normalised key, so "answer only above λ" carries a finite-sample guarantee on the error rate (certified targets — curated: 5 %; register: 5 %). Below the threshold the string goes to review. |
| **Reads context** | `CA` in a US *jurisdiction-of-formation* field is California, in a *country* field Canada; `Georgia` is the US state for a US register and the country otherwise. The request carries the field and the register's country. |
| **Typos, abbreviations, many languages** | Trained on country names from Unicode CLDR and Wikidata in many languages and scripts (see the lexicon under How it works), GeoNames places, real register strings, and generated variants (keyboard typos on real layouts, transliterations, formatting noise) that passed quality gates and a human audit. Of the 4,997 evaluation strings, 5 are not in Latin script, so accuracy on other scripts is not measured. |
| **Small and fast** | One 8-bit ONNX file; serving needs no PyTorch and no GPU — onnxruntime, tokenizers and NumPy do the work, offline. |
| **Measured, and corrected in the open** | Apache-2.0 code and weights. Pre-registered hypotheses, a test read once, baselines including a 35B LLM and a context-aware lexicon, every number generated from `results/`, and the corrections an external review prompted (certificate units, context baseline, label types) published with the evidence. |

## How it works

```mermaid
flowchart LR
    A["Free text<br/>+ field + register"] --> B["mmBERT-small encoder<br/>trimmed vocabulary<br/>int8 ONNX"]
    B --> C["Two heads<br/>country + not-a-place<br/>US state"]
    C --> D["Calibration<br/>temperature + certified<br/>threshold per domain"]
    D -->|confident| E["ISO code<br/>AT · GB · US-GA"]
    D -->|not confident| F["Abstain<br/>candidates → review"]
```

1. **Lexicon** — 372,683 names in 1,274 languages (CLDR 47, Wikidata, codes, reviewed overrides); 86,406 distinct keys, 1,947 kept as genuinely ambiguous. Ambiguity is explicit: a key maps to a *set* of codes.
2. **Training strings** — the lexicon, register strings of the training split labelled by a person
   or by the register's own code, and generated variants: keyboard typos on real layouts (fitted to
   real typo statistics), transliterations, formatting variants, place context (GeoNames cities
   and regions with the country name), two-country strings, compass and region qualifiers,
   Canadian province codes in US jurisdiction fields, and non-place strings (placeholders,
   generated company names, legal terms, dates, street lines). Every generator release the model
   uses passed quality gates — collision checks against all names, no overlap with evaluation
   strings, reproducibility, measured usefulness on held-out real strings — and a human audit of
   its labels; realism against real typos is reported, not gated ([model card](model_card.md)).
3. **Model** — `jhu-clsp/mmBERT-small` fine-tuned with two heads (country + not-a-place, US
   state), the field context as a first segment; its vocabulary trimmed to the tokens of the
   training texts, exported to ONNX with 8-bit weights (an int8 embedding table and 8-bit
   `MatMulNBits` matrix products, which the CPU runtime computes with int8 activations).
4. **Calibration** — per-domain temperatures and thresholds chosen by fixed-sequence testing:
   temperatures and the order of candidate thresholds are fitted on one set of held-out real
   strings, and the error-rate certificate is computed on another, counting one unit per register
   and normalised key (the same string in several fields of a register is not an independent
   draw). Candidate lists hold every code with calibrated probability ≥ 0.05 (at most three); they
   are suggestions, not certified.

## Quick start

**1. Install.** You need [uv](https://docs.astral.sh/uv/) and Python 3.12. Serving needs no
PyTorch and no GPU.

```bash
git clone https://github.com/aliildan/country-code-decide
cd country-code-decide
uv sync --no-default-groups --group serve
source .venv/bin/activate        # plain `uv run` would sync the full training stack (PyTorch)
```

**2. Download the model** (int8 ONNX, tokenizer, calibration; the fp32 reference file is skipped):

```bash
uvx --from huggingface_hub hf download aildan/country-code-decide-small \
  --exclude model.onnx --local-dir models/country-code-decide-small
```

**3. Code strings in Python.**

```python
from countrycode.infer.pipeline import CountryCoder

coder = CountryCoder.load("models/country-code-decide-small")
reg = dict(domain="register", alpha=0.05)   # register calibration, certified 5 % error target

coder.code("Østerrike", field="country", **reg).target                          # 'AT'
coder.code("Georgia", field="jurisdiction", register_country="US", **reg).target  # 'US-GA'
d = coder.code("Georgia", **reg)            # no context: abstains
d.abstain, d.candidates                     # (True, ('GE', 'US-GA'))
coder.code("Deleware", field="jurisdiction", register_country="US",
           domain="register", alpha=None).target                                # always answer: 'US-DE'
```

`field` is `country`, `jurisdiction`, `nationality` or `unknown`; `register_country` is the
ISO code of the register (or `US-XX` for a US state register). `alpha` is the error-rate target
(`None` always answers); `domain` picks the calibration — `"register"` for register and form
fields, `"curated"` for curated name lists. Without a domain the stricter of the two policies
applies; that merged policy is conservative but not itself certified. `code_batch` takes lists.

**4. Or run the server.**

```bash
python server/app.py --bundle models/country-code-decide-small
curl -s localhost:8320/v1/countrycode -H 'content-type: application/json' -d '{
  "items": [{"text": "Untted Klngdom", "field": "country", "domain": "register"},
            {"text": "CA", "field": "jurisdiction", "register_country": "US", "domain": "register"}],
  "alpha": 0.05}'
```

`POST /v1/countrycode` codes a batch; `POST /v1/systemone` answers the typed questions `country`,
`us_state` and `is_country` in the System One schema (probabilities + `abstain`).

## Accuracy

- Country-level accuracy (right country; a US state counts as US): 0.912 (highest: v1_model 0.921).
- On the 33 strings not in the lexicon (no exact name match) the model's accuracy is 0.212.
- At the certified 5 % error target the model answers 88% of the strings automatically with a realised error of 2.5 %; non-places get a code 0.0 % of the time (n = 4). The 5 % target is certified over 318 register units (one per register and normalised key); 1 % and 2 % are not.
- The zero-shot LLM (qwen3.5_35b-a3b-q4_K_M) is less accurate when every string must be answered (0.850 vs the model's 0.886); its own confidence covers 71% of the strings at 5 % empirical risk, without a certificate. It is ~29× slower (the LLM on a GPU, this model on a CPU).


The guarantee is an average over strings like the calibration strings, and the errors concentrate on hard ones: at the 5 % target 13.1 % of the 61 answered hand-labelled strings are wrong, 0.0 % of the 256 answered strings that an exact lexicon match labelled.

**The certificate, corrected.** The pre-registered certificate treated the 592 register calibration strings as independent draws and certified 2 % and 5 %. The same string often appears in several fields of a register, so they are not independent: they form 318 register-and-key units. Counted per unit — a correction made after the test read, prompted by an external review — 2 % is not certified, and 5 % is, at λ = 0.762. This release (small-v1.2.1) ships that calibration; the weights are unchanged.

## Limitations and responsible use

- **A lexicon is enough for clean fields.** On the fresh registers an exact lexicon with the
  training context rules is as accurate as the model; the model's advantage is on misspelled and
  abbreviated register strings, and it was measured on held-out strings of registers whose other
  strings were in training. On strings with no exact lexicon match in the fresh registers it is
  right far less often (see Accuracy), which points to register-specific learning.
- **The certificate is an average, per target.** It holds for strings drawn like the calibration
  strings (register fields), counted per register and normalised key, each target on its own; the
  errors concentrate on hard strings. Recalibrate before relying on it for another source. The
  merged policy used without a `domain` is not certified, and the 1 % and 2 % targets are not.
- **One person labelled** the register strings and audited the generated data; the blind
  re-labelling measures consistency, not agreement between people, and the test labels were
  labelled once.
- **Measured on Latin script.** The training data cover many scripts; the evaluation strings are
  almost all Latin (see above).
- **One training seed.** Every run used seed 13; the usefulness gate (G3) compared runs whose
  run-to-run spread is about as large as its margin (0.5 points).
- **Known gaps:** bare Canadian province codes in US jurisdiction fields (`ON`, `BC`) are not
  recognised — every real such string is an evaluation string, so the no-overlap gate removed
  them from the generated province variants; `Congo` without context is answered as `CG` although
  it may mean either Congo.
- **One field at a time.** Full postal addresses and subdivisions other than US states are out of
  scope.
- **Keep a person in the loop.** Not legal advice; abstentions and candidate lists need human
  review, and no decision about a person should rest on this model alone.

## Reproduce

The whole pipeline runs on one machine; training used one RTX 5090.

```bash
uv sync                                   # full stack incl. PyTorch (cu128 wheels on Linux)
make lexicon real synth                   # official sources → lexicon, real strings, generator releases + gates
uv run python -m countrycode.train fit --config configs/train/small-v12f.yaml
uv run python -m countrycode.infer trim --run runs/small-v12f --out runs/r-trim-C --synth-texts --no-single-chars
uv run python -m countrycode.infer bundle --run runs/r-trim-C --out dist/countrycode-small-v1.2 --version v1.2
scripts/final_run_v12.sh small-v1.2 small-v12f    # release 1.2: G1 stamp, calibration, the pre-registered read
scripts/final_run_v121.sh                         # release 1.2.1: unit-level certificate, post-hoc evaluation
uv run python scripts/make_docs.py        # README.md and model_card.md from results/
```

What is not in this repository: the human gold labels of the evaluation strings and the human
audit verdicts of the generated data (aggregate results only, in [`results/`](results/)).
Without them, training reproduces, but calibration and evaluation need your own labelled strings.
`make synth` also builds generators the released model does not use (OCR, LLM paraphrases),
which need a local OCR engine and cached hosted-LLM outputs.
